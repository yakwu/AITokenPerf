## 1. 背景与问题

AITokenPerf 是面向大模型 API 的主动拨测监控平台。当前前端把**同一份数据**摆成多个割裂入口，概念重叠，用户（运维使用者、非深度后端）容易迷路。

已核实的事实：

- 数据库**没有 `sites` 表，只有 `profiles` 表**。`/sites`（站点）的"新建站点"和 `/config`（连接配置）的"保存配置"**都 POST 到同一个 `/api/profiles/save`**，建出来一模一样。
- `/api/sites/summary`、`/api/sites/trend` 内部都用 `profile_name`。"站点"就是 profile 的展示别名。
- 现网顶栏可见导航 **4 项**：概览、目标站点、历史与对比、定时任务（`App.vue` tabs）。`/models`、`/settings`、`/admin-users` 在头像下拉；**`/config` 没有任何导航入口**，只能靠书签到达——一个隐藏的重复页面。
- 定时任务有**两个创建入口**（顶栏 `/tasks` 全局页 + 站点详情里的 tab），两个表单字段不同步，但都走 `/api/schedules`。其创建表单一次性铺开 **13 个字段**（任务名/频率/模型/并发/模式/超时/时长/max_tokens/system+user prompt/告警开关/webhook/阈值）——当前最重的配置场景。
- 模型有三处概念重叠：模型库（全局价格字典）、"我的模型"（中间层）、站点自己的 `models` 列表。
- "单次拨测"把两种语义不同的测试混在一个表单：低并发探活式验证 vs 高并发压测；且现网并发是**单选**（`selectedConcurrency` 单值），无法一次跑出梯度曲线。

### 用户的真实心智模型

```
站点（渠道 = base_url + key）
   └── 多个被测模型（opus4.7 / opus4.8 / sonnet4.6 … 随新模型发布动态增删，如 opus4.9）
          └── 对站点+模型做三类测试
```

| 测试类型 | 目的 | 并发 | 触发 | 最关注 | 告警 |
|---|---|---|---|---|---|
| 准入（体检） | 新站点/新模型能不能用、值不值得接 | 低（1） | 手动一次 | 连通性、TTFT、成功率、输出合理性 | 否 |
| 多并发压测 | 容量上限、性能拐点 | 高（梯度 1→10→50→100） | 手动一次 | 各并发下的延迟/吞吐/成功率曲线 | 否 |
| 持续连续性 | 长期稳定性、基础性能退化 | 固定低并发（1~2） | 定时自动 | 趋势、退化检测、成功率 | 是 |

## 2. 设计目标与非目标

### 目标（按优先级）

1. **易用性第一——查看场景和配置场景同等重要**。每个配置动作都要更少步骤、更少跳转、更合理默认。高频动作（加新发布模型、加完顺手开持续监控）必须顺手。
2. **概念去重**：一个数据实体一个入口，消除"站点/连接配置/模型库"重叠与"定时任务"双入口。
3. **测试语义分离**：准入（体检）/ 压测 / 持续监控 目的清晰，历史与趋势不再混看。

### 非目标（本次不做，避免范围膨胀）

- 不做告警升级（延迟/环比告警、状态机去抖）——另一个 P0 主题。
- 不做动态基线着色——另一个 P0 主题。
- 不实现统一诊断套件——已有独立设计，本次只在"测试"结果里预留"诊断"展示位（现网 `SiteTestTab` 已有诊断子区，沿用）。
- 不改指标计算逻辑（TTFT/TPOT/E2E 算法不动）。
- 不改 `profiles`、`results` 表既有结构与历史数据语义（只新增一列，见 §6）。

## 3. 目标信息架构

### 顶层导航：聚焦到 3 个可见 tab + 下拉

现网顶栏 4 项里，「定时任务」降级（见下），其余保留：

| 顶栏可见 | 说明 | 变化 |
|---|---|---|
| 📊 概览 | 全局健康快照 + **全局任务"只读+轻操作"总览** | 吸收原 `/tasks` 全局视图 |
| 🌐 目标站点 | 唯一的渠道管理与测试中心 | 保留并增强（详情见 §4） |
| 🕑 历史与对比 | 全局检索 + 对比 + 诊断 + 按 `test_kind` 过滤 | 增过滤，否则不动 |
| 头像下拉 | 模型库（纯价格字典）、设置、管理员 | 模型库砍"我的模型"中间层 |

**真实改动（不吹"导航变少"）**：
- **删 `/config`**：这个隐藏的重复页面去掉，连接信息的编辑回到站点详情「设置」tab。
- **取消定时任务双创建入口**：`/tasks` 顶栏 tab 去掉，创建/编辑统一回站点详情「持续监控」tab；全局"所有站点的持续监控任务"以**只读+轻操作**总览并入概览（见 §4.1）。
- **模型库**砍掉"我的模型"中间层，站点直接从库里挑模型。

### 站点详情：按测试目的分 4 个 tab

```
站点详情 · A站点   [🟢健康 · base_url · 3个模型 · 切换站点▾]
├─ 概况          ← 本站点各模型健康快照（情境化默认，见 §4.1）
├─ 测试          ← 一个 tab 内用 [体检 | 压测] 切换（§4.2）
├─ 持续监控      ← 定时 · 趋势 · 退化 · 告警（§4.4）
└─ 设置          ← 连接信息 + 模型清单增删（加 opus4.9 在这，§4.5）
```

模型不是独立 tab，而是**每种测试里"选测哪些模型"的维度**；模型清单的增删收在「设置」。

## 4. 各 tab 详细设计

### 4.1 概况 + 站点列表的"找得到"能力
- **概况**：各模型一行（TTFT P50 / 出字速度 / 成功率 / 最近结果时间 / 是否有持续监控在跑），每行可快捷跳到"对该模型测试/看趋势"。
- **情境化默认 tab**：站点**无任何测试数据**（新站点）默认落「测试」，进来就能跑准入；**有数据**默认落「概况」看健康。避免老用户多一跳、新用户少一跳。
- **站点列表（`SitesView`）增强**——几十个站点时的高频需求：
  - **收藏置顶**常看的几个站点；
  - **健康站点默认折叠**，异常站点优先展开（一眼看到要处理的）；
  - 搜索 + 状态筛选 chip 沿用现状。
  - 分组/标签列为 🟢 可选（§11），收藏与折叠本期做。
- **概览页全局任务总览**：默认按站点折叠或只显示异常任务，避免几十个任务变成一面墙。

### 4.2 测试 tab（体检 / 压测 切换）
顶部两枚大 pill 切换，**输入共用、只改并发预设与结果模板**：

- **体检（准入）🩺**：并发=1，少量请求，标准 prompt，**几乎零配置一键跑**。输出体检报告卡：✅能否连通、TTFT、成功率、平均输出 tokens、输出是否合理（非空/tokens>0）。预留诊断展示位。
- **压测 🔥**：**新增并发梯度多选**（预设 1→10→50→100，可改）+ 模式 burst/sustained。输出容量曲线（X=并发，Y=TTFT P50/P95、吞吐、成功率）。
  - ⚠️ 工作量提示：现网并发是单选 chip，梯度多选 + 曲线图是**新增 UI**（后端 `concurrency_levels` 已支持数组），实现期按新增估。
- 两者均复用 `client.py`/`run_burst`/`run_sustained` 采集逻辑，不新增测量代码。

### 4.3 （并入 4.2，无独立 tab）

### 4.4 持续监控 📈
- **最小创建表单（硬要求）**：默认只暴露 **3 个可见字段——模型（默认带全部）、频率（默认值）、告警开关**。其余（并发固定 1~2、模式、超时、时长、max_tokens、prompt、webhook、阈值）全部折叠进「高级」。与"持续监控锁定低并发"一致。这是对现状 13 字段表单的直接瘦身。
- **加模型顺手开监控的交互契约**：在「设置」加模型时可勾"同时加入持续监控"。勾选后**静默创建**一条 schedule：`name=<模型>-持续监控`、默认频率、并发 1、**告警默认关**；若该模型已有持续监控任务则跳过并提示。完成后 toast："已加入持续监控（点此去配告警）"。不跳转、不二次填表。
- **输出**：趋势图按 `test_kind` 与并发隔离绘制（不与压测数据混画）+ 最近运行 + 告警状态。
- 唯一会触发告警的测试类型；告警配置沿用现状（webhook+阈值），告警升级是后续主题。

### 4.5 设置 ⚙️
- 连接信息：base_url、api_key（脱敏）、协议/厂商。
- 模型清单增删：搜索模型库即加（输入 `opus4.9` → 匹配 `claude-opus-4-9`(带价格) → 加入）；找不到有"自定义模型"兜底。**现状 `ModelSelector` 已接近达标，重构后不得退化**（见 §5）。
- 删除站点。

## 5. 配置场景易用性验收点（一等需求，硬性）

1. **加新模型不退化且 ≤3 步**：设置→搜索→加入；加入时可勾"同时加入持续监控"（§4.4 契约）。现状已接近达标，重构不得变差。
2. **建站点字段最小化**：必填只留名称、base_url、key、至少一个模型；其余给默认。
3. **建持续监控默认 ≤3 个可见字段**（模型/频率/告警开关），其余折叠高级。
4. **测试不用填一堆参数**：体检几乎零配置；压测给预设梯度。
5. **不跨页面找配置**：一个站点的所有配置都在它的详情页里，不再去 `/config`、`/tasks` 之间跳。
6. **告警响应快**：从飞书告警/概览总览能对一条任务原地"暂停/立即执行"，编辑一跳直达。
7. **改动有即时反馈**：保存/加入/启停都有 toast/状态提示。

## 6. 数据层改动（唯一的数据库改动）

准入与压测在系统里都是 `source=manual`，仅靠 `mode`/`concurrency` 无法稳定区分。新增一列标识测试类型。

- `results` 表新增 `test_kind TEXT`，取值 `admission` / `stress` / `continuous`。
  - SQLite 与 PostgreSQL 两套建表语句同步新增（`app/db.py`）。
  - 写入：`db.save_result()` 落该字段；由发起测试的入口决定取值（体检→admission，压测→stress，定时→continuous）。
  - **回填**：老数据该列为空 → 存 `legacy`，展示时按 `source` 推断归类（`scheduled`→持续监控；`manual`→历史里归"未分类"，不强制重写历史行）。
- 历史页 `/history` 与站点趋势：增加按 `test_kind` 过滤；趋势图默认只画同一 `test_kind`（持续监控锁定并发）以防失真。
- `profiles` 表结构**不变**。
