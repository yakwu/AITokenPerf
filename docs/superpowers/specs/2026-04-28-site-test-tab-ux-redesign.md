# SiteTestTab UX 重设计：基准测试与渠道诊断分离

## 背景

当前 SiteTestTab.vue 中，"渠道诊断"和"基准测试"共用同一个表单区域。用户填写的系统提示词、用户提示词对诊断完全无效（诊断使用内置固定 prompt），但 UI 上没有明确区分，容易产生误解。

## 目标

将"基准测试"和"渠道诊断"拆分为两个独立 Tab，各自有专属配置区域，消除用户困惑。

## 设计

### 页面结构

```
┌─────────────────────────────────────────┐
│ 选择模型                                │
│ [模型标签选择器]  ← 页面顶部，Tab 外共享│
│                                         │
│ ┌──────────┐ ┌──────────┐              │
│ │ 基准测试  │ │ 渠道诊断  │  ← Tab 切换 │
│ └──────────┘ └──────────┘              │
│                                         │
│ ═══ 基准测试 Tab ══════════════════════ │
│ 测试模式: [Burst] [Sustained]           │
│ 并发数: 1  5  10  20  50  100           │
│ ▼ 高级参数                              │
│   每级请求数 / 最大输出 Tokens / 超时    │
│   持续时长(Sustained)                   │
│   系统提示词 / 用户提示词               │
│   ☐ 缓存测试                            │
│                                         │
│ [开始测试] [连通性验证]                  │
│                                         │
│ ═══ 渠道诊断 Tab ══════════════════════ │
│ ℹ 诊断使用内置固定 prompt 测试渠道的    │
│   缓存支持情况，不使用上方的提示词配置。 │
│   预计消耗 ~10 个请求、~25K tokens。    │
│                                         │
│ [开始诊断]                              │
│                                         │
│ (诊断结果卡片，仅在此 Tab 显示)         │
│   模型名 | 状态标签 | 命中率 | 风险     │
└─────────────────────────────────────────┘
```

### 关键规则

1. **模型选择器**：放在 Tab 上方，两个 Tab 共享同一份 `selectedModels`
2. **基准测试 Tab**：只包含测试相关配置（模式、并发、高级参数、提示词、缓存测试）和操作按钮（开始测试、连通性验证）
3. **渠道诊断 Tab**：只包含说明文字、诊断按钮和诊断结果展示。不显示任何提示词输入框
4. **诊断结果**：仅在渠道诊断 Tab 内显示，不污染基准测试 Tab
5. **"缓存测试" checkbox**：保留在基准测试的高级参数中，仅影响基准测试
6. **Tab 状态**：默认选中"基准测试"Tab

### 改动范围

仅修改 `frontend/src/components/SiteTestTab.vue`，不涉及后端改动。

### 具体改动

1. **新增 Tab 状态**：`activeTab = ref('bench')`，值为 `'bench'` 或 `'diag'`
2. **模型选择器上移**：从 form-grid 内部移到 Tab 上方
3. **Tab 切换 UI**：两个 Tab 按钮，选中态高亮
4. **基准测试区域**：包裹在 `v-show="activeTab === 'bench'"` 中
5. **渠道诊断区域**：包裹在 `v-show="activeTab === 'diag'"` 中，包含：
   - 说明文字（内置 prompt、不使用用户提示词、token 消耗预估）
   - 诊断按钮（从原 action buttons 区域移入）
   - 诊断结果卡片（从原底部区域移入）
6. **移除旧元素**：
   - 移除原 action buttons 区域中的"缓存诊断"按钮和"诊断中..."按钮
   - 移除原底部的诊断结果展示区域
   - 移除原高级参数中的"渠道诊断"checkbox（`enableDiagnostics`）

### 诊断结果卡片保留现有样式

```
模型名 | 状态标签(绿/黄/红/灰)
缓存命中率: xx%  风险: low/medium  置信度: xx%
```

## 不变的部分

- 后端 API 不变
- 诊断逻辑不变（`channel_diagnostics.py`）
- 基准测试逻辑不变
- 连通性验证不变
- 实时结果展示不变
